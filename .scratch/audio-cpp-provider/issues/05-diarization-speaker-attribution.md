# 05: Диаризация — спикеры у сегментов транскрипта

**What to build:** После транскрибации встречи провайдером audioCpp приложение прогоняет запись через Nemotron-3-Diarization и атрибутирует сегменты транскрипта спикерам: у каждого сегмента появляется метка спикера, отображаемая в UI транскрипта. Спикеры идентифицируются порядком появления (см. GLOSSARY.md: «спикер», «поворот спикера»). Миграция БД добавляет nullable-поле `speaker` у сегмента транскрипта; старые встречи без диаризации открываются как раньше. Атрибуция — наложение поворотов спикера на сегменты по временным меткам; правило граничных случаев (сегмент на стыке двух поворотов, сегмент без покрытия) зафиксировано тестами чистой функции наложения. Диаризация работает в offline-режиме; стриминг — вне объёма.

**Blocked by:** 04 (Транскрибация встречи провайдером audioCpp)

**Status:** resolved

- [x] После транскрибации встречи через audioCpp автоматически выполняется диаризация (если скачана модель Nemotron)
- [x] У сегментов транскрипта в UI отображаются метки спикеров
- [x] Миграция БД обратимо-применима: старые встречи открываются, поле speaker nullable
- [x] Чистая функция наложения поворотов на сегменты покрыта юнит-тестами граничных случаев
- [x] Если модель диаризации не скачана, транскрипт работает без меток спикеров, пользователь видит подсказку
- [x] Диаризация на длинных записях (десятки минут) не приводит к зависанию UI

## Answer

Диаризация встроена как постобработка после транскрибации audioCpp.

**Движок и поток (offline).**
- `audio_cpp_engine/engine.rs`: в трейт `AudioCppModel` добавлен `diarize()`, а `NativeAudioCppModel` держит отдельную ленивую `diar`-сессию (`DIAR_TASK`/`OFFLINE_MODE`) рядом с asr-сессией. `AudioCppModel::supports("diar","offline")` — гейт возможностей.
- `audio/transcription/audio_cpp_diarizer.rs`: `AudioCppDiarizer` — модель и сессия живут на выделенном потоке `audiocpp-diar-session` (хендлы audio.cpp не потокобезопасны), запросы идут через канал и ожидаются асинхронно, поэтому многочасовая запись не блокирует tokio-runtime и UI. Вход — контракт пайплайна 16 кГц mono f32. Тесты подтверждают, что все нативные вызовы остаются на потоке, загрузившем модель.
- `audio/transcription/diarization_service.rs`: оркестрация — `select_diarization_model` выбирает только установленную модель задачи `diar` (Missing/Downloading/Corrupted пропускаются), `diarize_transcript` конвертирует сэмплы поворотов в секунды и накладывает их на границы сегментов, `diarize_segments`/`diarize_recording_folder` — удобные обёртки для batch-путей и для сохранённой встречи.

**Правило атрибуции (чистая функция).**
- `audio/transcription/diarization.rs`: `attribute_segments_to_speakers(segments, turns)` — сегмент получает спикера с наибольшим перекрытием; при равенстве побеждает более ранний поворот; сегмент без покрытия остаётся `None`; нулевая длина относится к повороту, содержащему момент старта; спикеры перенумеровываются по порядку появления (`speaker_0`, `speaker_1`, …), а не по id движка.
- 11 юнит-тестов фиксируют граничные случаи: сегмент целиком в повороте, стык двух поворотов, точная ничья на границе, отсутствие покрытия, пустой список поворотов, смена спикера внутри сегмента, нулевая длина, неупорядоченные повороты, нумерация по появлению.

**БД.**
- `models::Transcript` и `api::TranscriptSegment`/`MeetingTranscript` получили `Option<String> speaker` (serde: отсутствует, когда `None`), `MeetingDetails` — `folder_path` для поиска записи.
- Все три INSERT-пути (живое сохранение через `TranscriptsRepository`, ретранскрибация, импорт) пишут `speaker`; чтение (`get_meeting`, `get_meeting_transcripts_paginated`) возвращает его.
- Колонка уже добавляется существующей миграцией `20251110000001_add_speaker_field.sql` (`ALTER TABLE transcripts ADD COLUMN speaker TEXT` — nullable). Тесты `database/migrations_tests.rs` прогоняют реальную цепочку миграций на чистой in-memory БД, вставляют «до-диаризационную» строку без `speaker` (читается как `NULL`) и проверяют round-trip метки через репозиторий.

**Встраивание в потоки.**
- Импорт и ретранскрибация: при `BatchEngine::AudioCpp` 16-кГц аудио сохраняется до VAD, после транскрибации вызывается `diarize_segments`, метки пишутся в БД вместе с сегментами. Другие провайдеры диаризацию не запускают.
- Живой пайплайн: после того как stop-flow сохранил встречу (`api_save_transcript` вернул `meeting_id`), `useRecordingStop` при провайдере `audioCpp` вызывает команду `audiocpp_diarize_meeting` (идемпотентная: диаризует сохранённую встречу по её папке и обновляет `transcripts.speaker`). Вызов fire-and-forget, навигация его не ждёт; ошибка не фатальна (встреча уже сохранена), а по завершении рассылается событие `transcripts-updated`, на которое страница встречи отвечает refetch'ем. Для Whisper/Parakeet команда не вызывается (тест в `tests/lib/live-diarization.test.ts`).
- Если модели нет или проход упал — транскрипт сохраняется без меток, а в UI уходит событие `diarization-unavailable` с подсказкой скачать Nemotron (тосты в `useImportAudio` и `RetranscribeDialog`).

**UI.**
- `VirtualizedTranscriptView` показывает у сегмента чип `Speaker N` (1-based, только для `speaker_N`; легаси-значения `mic`/`system` из переиспользованной колонки и любые неизвестные id чип не получают), `TranscriptSegmentData`/`Transcript`/`MeetingTranscript` прокидывают `speaker` через `usePaginatedTranscripts`, обе `TranscriptPanel`.

**Верификация.**
- `cargo test --lib`: **495 passed, 0 failed, 7 ignored** (включая 11 тестов правила наложения, 5 тестов выбора/service-слоя, 3 теста миграций).
- `bun test`: baseline + новые UI-тесты меток спикера (включая легаси `mic`/`system` без чипа) и тесты live-диаризации зелёные. Единственное падение (`empty summary state > renders a persistent retryable error`) и 5 межфайловых ошибок моков — предсуществующие, воспроизводятся на чистой интеграционной ветке.
- `tsc --noEmit` чист.
- **Не проверено:** живой прогон Nemotron на реальной длинной записи (нет весов/нативной библиотеки на этой машине) и качество разметки спикеров на реальных встречах; UI проверен компонентными тестами, не в живом окне Tauri.
