# 06: Ретранскрибация и импорт файлов через audioCpp

**What to build:** Провайдер `audioCpp` становится доступен во всех путях выбора движка транскрибации: пользователь может перетранскрибировать существующую встречу моделью audioCpp (например, сравнить качество с Whisper) и транскрибировать импортированный внешний аудиофайл через audioCpp. Поведение согласуется с живым пайплайном: те же сегменты, те же метаданные модели, диаризация применяется и здесь, если скачана модель.

**Blocked by:** 04 (Транскрибация встречи провайдером audioCpp)

**Status:** resolved

- [x] В диалоге перетранскрибации встречи доступен провайдер `audioCpp` и его модели
- [x] Перетранскрибация встречи через GigaAM заменяет транскрипт корректно, старые данные не портятся
- [x] Импорт внешнего аудиофайла транскрибируется через audioCpp с тем же результатом, что и живой пайплайн
- [x] Диаризация применяется к результатам перетранскрибации/импорта, если скачана модель Nemotron
- [x] Ошибки (не загружена модель, сбой движка) обрабатываются как в живом пайплайне

## Answer

Провайдер `audioCpp` подключён в оба batch-потока (перетранскрибация и импорт) через тот же трейт-контракт `TranscriptionProvider`, что и живой пайплайн:

- **Выбор движка.** В `audio/common.rs` добавлен `BatchEngine::{Whisper, Parakeet, AudioCpp}` с маппингом `from_provider_name` (неизвестный/`None` провайдер сохраняет прежний дефолт Whisper). `retranscription.rs` и `import.rs` заменили флаг `use_parakeet` на `BatchEngine`; транскрибация сегментов идёт через `provider.transcribe(samples, language)` — тот же вызов, что у worker'а живого пайплайна, те же сегменты VAD и метаданные модели. Замена транскрипта — в одной транзакции DELETE+INSERT (существующее поведение, не менялось).
- **Загрузка конкретной модели.** `engine::get_or_init_audio_cpp_provider` рефакторен в обёртку над новым `get_or_init_audio_cpp_provider_with_model(app, requested_model)`: кеш-провайдер переиспользуется только если уже загружена запрошенная модель; для batch-задач с явной моделью конфиг-провайдер не валидируется и фолбэка на другую модель нет — новая чистая функция `audio_cpp_engine::transcription::select_requested_transcription_model` отклоняет модель не из каталога (`ModelNotReady::NotFound`), диаризационную (`WrongTask`) или неустановленную (`Status`) с пользовательским сообщением. Это зеркалит поведение Whisper/Parakeet в batch-путях и защищает сравнение качества моделей.
- **Выгрузка.** `unload_engine_after_batch` принимает `BatchEngine`; для audioCpp вызывает `audio_cpp_engine::transcription::unload_provider()` (освобождает сессионный поток и модель) с тем же пропуском при живой записи.
- **Язык.** Подсказка языка пробрасывается как есть: GigaAM игнорирует её (логирует), `auto-translate` отклоняется провайдером с объяснением «только Whisper» — как в живом пайплайне. Диалоги (`RetranscribeDialog`, `ImportAudioDialog`) для audioCpp показывают заметку «Language selection isn't supported» и шлют `language: null`, зеркаля Parakeet.
- **UI.** `useTranscriptionModels` дополнен выборкой `audiocpp_get_available_models`: предлагаются только установленные (`Available`) модели задачи `asr` — диаризационная модель и недокачанные артефакты отфильтрованы; сбой команды audioCpp не ломает список других провайдеров; сохранённая конфигурация `audioCpp` подсвечивается по умолчанию. Провайдер/модель диалога отправляются в команду как `provider: 'audioCpp'`.
- **Диаризация (тикет 05).** Атрибуция спикеров накладывается на сегменты после транскрибации, поэтому применится к результатам перетранскрибации/импорта автоматически, когда лендит; зависимостей от ветки 05 нет.
- **Тесты.** Rust: `BatchEngine::from_provider_name` (3 теста, `audio/common.rs`), `select_requested_transcription_model` (4 теста, `audio_cpp_engine/transcription.rs`); `cargo test --lib` — 460 passed, 0 failed. Frontend: `tests/hooks/use-transcription-models.test.tsx` (4 теста на список/фильтр asr/дефолт/сбой команды) — зелёные; `tsc --noEmit` чист. Поведение в Tauri-приложении с нативной библиотекой не проверялось (нет окружения с GUI); живой прогон GigaAM на реальной встрече остаётся ручной проверкой.
