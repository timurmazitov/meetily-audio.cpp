# Провайдер транскрибации audioCpp (GigaAM + Nemotron-3-Diarization)

Status: ready-for-agent

## Problem Statement

Пользователь Meetily ограничен двумя движками транскрибации: Whisper (универсальный, но слабый на русской речи относительно специализированных моделей) и Parakeet (английский). Диаризации в приложении нет вообще — пользователь не видит, кто из участников встречи что говорил, и вынужден либо слушать запись, либо использовать внешние инструменты. При этом существующие исследования (docs/research/) подтвердили: экосистема audio.cpp поддерживает и русскоязычную ASR (GigaAM v3 e2e CTC), и диаризацию до 8 спикеров (Nemotron-3-Diarization), но приложение не умеет с ними работать.

## Solution

Новый провайдер транскрибации `audioCpp` — третий рядом с Whisper и Parakeet, реализованный за существующим трейтом `TranscriptionProvider`. Движок — audio.cpp (0xShug0/audio.cpp), встроенный в процесс через C ABI. Пользователь выбирает провайдер в настройках, скачивает модели из HuggingFace через существующий UI управления моделями, транскрибирует встречи с качественным русским распознаванием и видит атрибуцию речи по спикерам в транскрипте. Решение зафиксировано в docs/adr/0001-audio-cpp-as-third-engine.md.

## User Stories

1. Как пользователь, я хочу выбирать провайдер транскрибации `audioCpp` в настройках, чтобы использовать движок audio.cpp.
2. Как пользователь, я хочу видеть в менеджере моделей аудио.cpp список поддерживаемых моделей с описанием, чтобы понимать, что я скачиваю.
3. Как пользователь, я хочу скачивать модель GigaAM v3 e2e CTC из настроек, чтобы транскрибировать русскоязычные встречи локально.
4. Как пользователь, я хочу скачивать модель Nemotron-3-Diarization из настроек, чтобы получать разметку спикеров.
5. Как пользователь, я хочу видеть прогресс скачивания модели, чтобы понимать, сколько ждать.
6. Как пользователь, я хочу отменять скачивание модели, чтобы не тратить трафик зря.
7. Как пользователь, я хочу удалять скачанные модели, чтобы освобождать место на диске.
8. Как русскоязычный пользователь, я хочу качественное распознавание русской речи, чтобы транскрипт был точным.
9. Как пользователь, я хочу видеть у каждого сегмента транскрипта метку спикера, чтобы понимать, кто говорил.
10. Как пользователь, я хочу, чтобы спикеры нумеровались по порядку появления, чтобы ссылаться на них в саммари.
11. Как пользователь, я хочу перетранскрибировать встречу с другой моделью аудио.cpp, чтобы сравнить качество.
12. Как пользователь, я хочу транскрибировать импортированный аудиофайл через audioCpp, чтобы обрабатывать внешние записи.
13. Как пользователь, я хочу получить понятное сообщение при выборе перевода с провайдером audioCpp, чтобы знать, что перевод доступен только у Whisper.
14. Как пользователь, я хочу, чтобы при ошибке загрузки модели приложение не падало, а показывало понятную ошибку.
15. Как пользователь на Linux, я хочу работу на CPU и Vulkan, чтобы использовать приложение без NVIDIA.
16. Как пользователь на Windows, я хочу установку через стандартный установщик без ручной установки рантаймов, чтобы приложение просто запускалось.
17. Как пользователь, я хочу, чтобы настройки провайдера и модели сохранялись между перезапусками, чтобы не настраивать заново.
18. Как пользователь с GPU NVIDIA, я хочу, чтобы движок использовал GPU, когда он доступен, чтобы транскрибация была быстрой.
19. Как пользователь, я хочу, чтобы существующие встречи, транскрибированные Whisper/Parakeet, продолжали открываться, чтобы не потерять данные.
20. Как разработчик, я хочу, чтобы вся работа с нативной библиотекой была изолирована в одном модуле-обёртке, чтобы миграция на другую форму интеграции была локальной.
21. Как разработчик, я хочу гейт по версии ABI при загрузке библиотеки, чтобы несовместимая версия отклонялась явно, а не крашила приложение.
22. Как разработчик, я хочу family-agnostic движок с авто-детектом семейства из GGUF, чтобы добавление новых моделей не требовало изменения FFI-слоя.
23. Как мейнтейнер, я хочу, чтобы дистрибутив включал лицензии движка и весов моделей, чтобы соблюсти условия Apache-2.0 / MIT / OpenMDW-1.1.

## Implementation Decisions

- **Движок**: audio.cpp, in-process FFI через C ABI (`libaudiocpp.so` / `audiocpp.dll` из релизных lib-архивов, пин на v0.9.4, ABI 0.2.0). Sidecar-процесс и transcribe.cpp отклонены (обоснование в ADR-0001).
- **Новый модуль-движок** (`audio_cpp_engine`): рукописный `extern "C"` биндинг (75 символов, официальных Rust-биндингов нет); opaque-обёртки над registry/model/session/request/result; `Send` вручную, `Sync` — нет; гейт по `audiocpp_abi_version()` (major must match, minor только добавляет entry points).
- **Потоковая модель**: хендлы не потокобезопасны — одна сессия на поток (соответствует существующему worker-pool); блокирующие вызовы только через `spawn_blocking`; число потоков задаётся в `audiocpp_backend_config`, не трогаем глобальный OpenMP.
- **Family-agnostic загрузка**: `family_hint = NULL`, авто-детект семейства из embedded spec в GGUF; проверка возможностей через `audiocpp_model_supports(model, task, mode)`.
- **Провайдер**: новая реализация трейта `TranscriptionProvider` (контракт: `transcribe` / `is_model_loaded` / `get_current_model` / `provider_name = "audioCpp"`), регистрация в диспетчере `TranscriptionEngine` по строке конфига `audioCpp`; существующая логика fallback-to-whisper не меняется.
- **Каталог моделей**: GigaAM v3 e2e CTC F16 — из репозитория `audio-cpp/audio.cpp-gguf` (НЕ handy-computer — их GGUF собран под transcribe.cpp, совместимость не подтверждена); Nemotron-3-Diarization BF16 — из `audio-cpp/Nemotron-3-Diarization-GGUF` (Q8_0 отклонён: не parity-safe, меняет границы поворотов спикера). Скачивание — через существующий механизм загрузки моделей с прогрессом/отменой; валидация magic GGUF. Модели разных задач (asr/diar) хранятся с метаданными семейства/задачи.
- **Входной сигнал**: 16 кГц mono f32 — существующий контракт аудио-пайплайна (48 кГц микс → VAD-сегменты 16 кГц). GigaAM ресемплит внутри себя, Nemotron требует 16 кГц на входе — дублировать ресемплинг не нужно. VAD остаётся Silero, не меняется.
- **Диаризация**: постобработка после транскрибации — прогон записи через сессию `diar`/offline, получение поворотов спикера, наложение на сегменты транскрипта по таймстемпам. **Миграция БД: nullable-поле `speaker` у сегмента транскрипта** (атрибуция на уровне сегментов, ADR-0001). Спикер идентифицируется порядком появления (см. GLOSSARY.md: «спикер», «поворот спикера»). Стриминговый режим диаризации — за скобкой.
- **Перевод**: GigaAM не поддерживает перевод — опция авто-перевода блокируется для провайдера `audioCpp` с явным пояснением; тихий fallback на Whisper отклонён (ADR-0001).
- **UI**: менеджер моделей аудио.cpp по образцу существующих менеджеров (список/скачать/отменить/удалить), значение `audioCpp` в селекторе провайдера настроек, отображение метки спикера у сегмента транскрипта.
- **Платформы первой итерации**: Linux (CPU + Vulkan) и Windows (Vulkan; бандл MSVC-рантайм DLL `msvcp140*`/`vcruntime140*`/`vcomp140` рядом с приложением). macOS — отдельным этапом. GPU-приоритет: CUDA → Vulkan → CPU, как в существующем авто-детекте.
- **Потребители движка**: новый провайдер подключается во всех местах выбора движка — живой пайплайн транскрибации, перетранскрибация, импорт файлов.
- **Лицензии**: Apache-2.0 кода audio.cpp (LICENSE в комплект дистрибутива, NOTICE не требуется); веса — MIT (GigaAM) и OpenMDW-1.1 (Nemotron), условия проверить при распространении.

## Testing Decisions

- **Хороший тест** проверяет внешнее поведение через шов, а не детали реализации: вход PCM/конфигурация → наблюдаемый результат (текст, сегменты, метки спикеров, ошибки).
- **Основной шов — трейт `TranscriptionProvider`** (существующий): тесты провайдера `audioCpp` гоняют контракт трейта с фейковым движком за FFI-обёрткой; реальная нативная библиотека в тестах не используется.
- **Наложение поворотов спикера на сегменты** — чистая функция (таймстемпы in → атрибуция out): юнит-тесты граничных случаев (сегмент на стыке двух поворотов, сегмент без покрытия, пустой список поворотов, спикер меняется внутри сегмента — правило атрибуции фиксируется тестом).
- **FFI-обёртка**: только юнит-тесты маппинга кодов статуса и thread-local ошибок; поведенческие тесты против живой библиотеки не пишутся.
- **Каталог и скачивание моделей**: тесты валидации magic GGUF и метаданных каталога — prior art: тесты загрузки в whisper_engine.
- **Приоритет**: существующие тестовые модули в transcription/worker и движках — образец организации.

## Out of Scope

- Замена или удаление провайдеров Whisper и Parakeet (audio.cpp — третий провайдер, ADR-0001).
- macOS / Metal (отдельный этап).
- Стриминговая диаризация и latency-профили Nemotron.
- Параллельная транскрибация длинных встреч через несколько сессий audio.cpp (эквивалент parallel_processor) — отдельное решение после MVP.
- Word timestamps: движок их отдаёт, но в UI не exposed (как и сейчас у Whisper).
- Q8_0-квант Nemotron (не parity-safe).
- Перевод для провайдера audioCpp.
- Legacy `backend/` — не трогаем.
- Смена VAD (Silero сохраняется).
- Транскрибация со speaker-лейблами одной моделью (например, nemotron_asr / MOSS-Transcribe-Diarize) — архитектура family-agnostic это позволит позже, но в объём не входит.

## Further Notes

- Риски (зафиксированы в docs/research/audio-cpp-c-api.md): производительность CPU/Vulkan для целевых семейств не замерена — нужен собственный бенчмарк (референс: `audiocpp_cli --metrics`), возможен пересмотр бэкенда; ABI main (0.3.0) отстаёт от релиза (0.2.0) — пин на релизных архивах; диаризация чувствительна к мелким изменениям входа на длинных записях — тестировать на длинных реальных встречах.
- Исследования первоисточников: docs/research/audio-cpp-c-api.md (C ABI, сборка, потоки, лицензии), docs/research/audio-cpp-vs-transcribe-cpp.md (выбор движка).
- Терминология: GLOSSARY.md (движок транскрибации, провайдер транскрибации, речевой сегмент, диаризация, спикер, поворот спикера).
- Этапы плана: (0) FFI-слой → (1) ASR-провайдер с GigaAM → (2) диаризация с миграцией БД → (3) сборка Linux/Windows + CI → (4) бенчмарки и полировка. MVP транскрибации готов после этапа 1; диаризация — инкрементально.
