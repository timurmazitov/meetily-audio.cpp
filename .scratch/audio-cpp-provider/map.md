# Map: audioCpp provider

## Decisions-so-far

- 07 windows-packaging-msvc-runtime — resolved: CI стейджит `audiocpp.dll` + MSVC-рантайм (`msvcp140*`/`vcruntime140*`/`vcomp140`) + Apache-2.0 лицензию из пинованного релиза v0.9.4 (`scripts/stage-audiocpp-runtime.ps1`, SHA256-пин) в `audiocpp-runtime/`, маппинг в корень установки через `tauri.windows.conf.json`; обнаружение рядом с exe из тикета 02 лейаут бандлера поддерживает без правок. Детали: `issues/07-windows-packaging-msvc-runtime.md` (Answer). Непроверено на живой Windows: сборка/установка установщика и запуск без VC++ Redist.
- 06 retranscription-import — resolved: audioCpp доступен в перетранскрибации и импорте через `BatchEngine` (`audio/common.rs`) и `engine::get_or_init_audio_cpp_provider_with_model` — точная запрошенная модель без фолбэка (`select_requested_transcription_model`, новый `ModelNotReady::NotFound`); те же сегменты/метаданные, что живой пайплайн, выгрузка через `unload_provider()`. UI: `useTranscriptionModels` фильтрует `asr`+`Available`, диалоги шлют `language: null` с заметкой. Диаризация (тикет 05) ляжет на эти пути автоматически. Детали: `issues/06-audiocpp-retranscription-import.md` (Answer). Непроверено в Tauri-приложении с нативной библиотекой.
