# Map: audioCpp provider

## Decisions-so-far

- 07 windows-packaging-msvc-runtime — resolved: CI стейджит `audiocpp.dll` + MSVC-рантайм (`msvcp140*`/`vcruntime140*`/`vcomp140`) + Apache-2.0 лицензию из пинованного релиза v0.9.4 (`scripts/stage-audiocpp-runtime.ps1`, SHA256-пин) в `audiocpp-runtime/`, маппинг в корень установки через `tauri.windows.conf.json`; обнаружение рядом с exe из тикета 02 лейаут бандлера поддерживает без правок. Детали: `issues/07-windows-packaging-msvc-runtime.md` (Answer). Непроверено на живой Windows: сборка/установка установщика и запуск без VC++ Redist.
- 08 gpu-backend-autodetect — resolved: вычислительный бэкенд audioCpp выбирается рантайм-авто-детектом (`HardwareProfile`, приоритет CUDA → Vulkan → CPU) в новом `audio_cpp_engine/backend.rs`; пинованные архивы ship варианты `cpu`/`vulkan`, поэтому CUDA-желание обслуживается Vulkan-вариантом (ICD NVIDIA); обнаружение библиотеки вариантное — `audiocpp-libs/<variant>/` рядом с exe, плоская раскладка как fallback (совместимо со staging 07), `AUDIOCPP_LIBRARY_PATH` побеждает всё; сессии создаются с токеном бэкенда; GGUF-модели бэкендо-агностичны. Задокументировано в `docs/GPU_ACCELERATION.md`. Детали: `issues/08-audiocpp-gpu-backend-autodetect.md` (Answer). Непроверено против живой CUDA/Vulkan-библиотеки (бенчмарк — отдельная задача).
