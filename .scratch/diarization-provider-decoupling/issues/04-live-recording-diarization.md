# 04: Живая запись — диаризация после каждой остановки, чем бы ни транскрибировали

Type: task
Status: ready-for-agent
Blocked by: 03

## Что сделать

Запись под провайдером Whisper или Parakeet и остановка должны давать транскрипт, который затем тихо получает метки спикеров — без тоста о том, чего пользователь не просил.

Сейчас после остановки проход запускается только при провайдере `audioCpp`. После тикета 03 решение принимается на нативной стороне, поэтому стоп-флоу достаточно вызвать команду после того, как встреча сохранена, — при любом провайдере.

Вызов остаётся неблокирующим: навигация и показ сохранённой встречи не ждут прохода, ошибка не фатальна, потому что встреча и транскрипт уже сохранены.

Обратная связь различается по контексту: пользователь не заказывал этот проход, поэтому `no_model`, `no_runtime` и `deferred` не показываются вовсе; тост показывается только при `failed`. Подсказка про модель диаризации остаётся в панели спикеров, где пользователь ищет спикеров.

## Критерии готовности

- [ ] После остановки записи проход запускается при провайдере `localWhisper`, `parakeet` и `audioCpp`
- [ ] Встреча и транскрипт сохраняются и открываются до завершения прохода
- [ ] Падение прохода не влияет на сохранение встречи и не блокирует навигацию
- [ ] Статусы `no_model`, `no_runtime`, `deferred` не показывают тост
- [ ] Статус `failed` показывает тост с причиной
- [ ] При успешном проходе открытая встреча получает метки без перезагрузки страницы
- [ ] Тесты покрывают все три провайдера и правило «какой статус молчит, какой говорит»

## Тесты (TDD)

Шов — тот же чистый модуль диаризации с инжектированным клиентом, что и в тикете 03; здесь добавляется решение «показывать или молчать» по статусу и проверка, что вызов не зависит от провайдера.

## Контекст

- Спека: `.scratch/diarization-provider-decoupling/spec.md` — решения «Оркестрация», «Статус и события», «Панель спикеров».
- Стоп-флоу уже сохраняет встречу до диаризации и рассылает событие обновления транскрипта; меняется только условие запуска и правило показа тоста.
- Запись ведётся двумя дорожками (микрофон и система) в смешанный файл; проход диаризации работает по сохранённому файлу встречи, а не по отдельным дорожкам.
