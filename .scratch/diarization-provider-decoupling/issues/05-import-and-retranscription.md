# 05: Импорт и перетранскрипция — диаризация после каждого сохранения

Type: task
Status: resolved
Blocked by: 03

## Что сделать

Импорт аудиофайла и перетранскрипция должны заканчиваться метками спикеров независимо от движка, а встреча должна появляться сразу, как готов текст, вместо ожидания диаризации.

Сейчас оба пути запускают проход только при движке audio.cpp и делают это инлайн, до сохранения встречи: пользователь ждёт диаризацию в прогресс-баре импорта или в диалоге перетранскрипции. После расцепления проход нужен всем трём движкам, поэтому инлайн-ожидание стало бы ожиданием того, что пользователь не заказывал.

Порядок меняется: встреча сохраняется с транскриптом, затем проход выполняется в фоне, а метки появляются через нативное событие обновления транскрипта. Из инлайн-последовательности уходит шаг «Assigning speakers…».

Отдельно убирается буфер 16-кГц аудио, который оба пути держали в памяти только ради диаризации: проход декодирует файл встречи повторно. Это стоит секунд и снимает сотни мегабайт, конкурирующие с моделью распознавания.

## Критерии готовности

- [x] Импорт файла заканчивается проходом диаризации при движке Whisper, Parakeet и audioCpp
- [x] Перетранскрипция заканчивается проходом диаризации при любом из трёх движков
- [x] Встреча становится доступной сразу после сохранения транскрипта, не дожидаясь прохода
- [x] Метки появляются в открытой встрече без перезагрузки страницы
- [x] Падение прохода не приводит к потере встречи или транскрипта и не отменяет импорт
- [x] Буфер аудио, сохраняемый только ради диаризации, удалён из обоих путей; аудио для прохода берётся из файла встречи
- [x] Из инлайн-последовательности импорта и перетранскрипции убран шаг «Assigning speakers…»
- [x] Повторная диаризация той же встречи перезаписывает метки целиком и согласует имена спикеров в той же транзакции
- [x] Тесты покрывают: проход запускается при каждом из трёх движков, ошибка прохода не роняет импорт и не роняет перетранскрипцию

## Тесты (TDD)

## Контекст

- Спека: `.scratch/diarization-provider-decoupling/spec.md` — решения «Оркестрация», «Статус и события».
- Импорт уже копирует файл в папку встречи до декодирования, поэтому повторное декодирование для прохода возможно без дополнительных шагов.
- Перетранскрипция удаляет и пересоздаёт транскрипты встречи, поэтому согласование имён спикеров после прохода обязательно и идёт в той же транзакции.
- Проход грузит нативную библиотеку и модель заново и отпускает их до возврата: память модели распознавания не удерживается.
- Нативная библиотека audio.cpp — предусловие; без неё проход возвращает статус «нет рантайма», а импорт и перетранскрипция завершаются нормально без меток.

## Comments

- Ветка: `diar-05` (`0228868`, `e6e118a`, `879181c`, `d69c891`), влита merge-коммитом `dbd3628`.
- Оба пути сохраняют встречу первыми и запускают проход в фоне через общий шов `diarization_run::schedule_after_batch`; решение «диаризовать ли» вынесено в `schedules_diarization` (возвращает `true` для всех трёх движков, параметр движка сохранён как единственное место для будущего гейта). Задача отвязана от гардов импорта/перетранскрипции, не читает их флаги отмены и не берёт мьютекс жизненного цикла движка, поэтому `unload_engine_after_batch` не блокирует и не отменяет её. `Err` прохода превращается в `warn!` через `background_pass_outcome`, а не в ошибку пакетного задания.
- Буфер 16 кГц удалён из обоих путей: VAD больше не возвращает `audio_samples`, проход декодирует файл встречи повторно. Шаг «Assigning speakers…» и инлайн-блоки удалены; `grep -rn "Assigning speakers"` пуст.
- Слушатели `diarization-unavailable` в `useImportAudio` и `RetranscribeDialog` больше не показывают тост безусловно: правило вынесено в `shouldToastDiarizationUnavailable` (тост только на `failed`), текст берётся из payload `message`.
- Найдено код-ревью и исправлено в `d69c891`: `transcripts.json` писался до прохода и оставался с `speaker: null`, расходясь с базой (в живой записи так было и раньше). Теперь общая операция после успешной записи меток перезаписывает файл теми же сегментами; ошибка записи только логируется и не меняет статус `ran`.
- Проверка: `cargo test --offline --lib` — **605 passed / 0 failed / 7 ignored** (baseline 597, прирост 8). `bun test` — 216 pass / 12 fail, все 12 — известный baseline mock-isolation (`recording-controls-stop`, `recording-state-shutdown`, `logo-doodle`), каждый файл зелёный отдельно. `tsc --noEmit` — без ошибок.
- Не проверено: живой прогон в Tauri-приложении (реальная библиотека audio.cpp, веса Nemotron, реальный импорт/перетранскрипция с метками, отсутствие `AUDIOCPP_LIBRARY_PATH` → `no_runtime`). Порядок блокировок выведен из кода, а не проверен тестом — по спеке тест на мьютекс не пишется.
