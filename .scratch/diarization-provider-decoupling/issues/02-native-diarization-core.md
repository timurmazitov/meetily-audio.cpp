# 02: Нативное ядро диаризации — одно решение, явные статусы, одна операция

Type: task
Status: resolved
Blocked by: None (можно начинать сразу)

## Что сделать

Сделать нативную сторону диаризации пригодной для вызова из трёх путей сохранения встречи и дать интерфейсу различимые причины отказа.

Сейчас результат прохода передаётся булевым флагом доступности плюс свободным текстом ошибки, поэтому UI не отличает «модель не скачана» от «нативный рантайм недоступен» от «проход упал». Ввести явный статус: `ran`, `no_model`, `no_runtime`, `deferred`, `failed`. Существующее булево поле доступности остаётся производным от `ran`, чтобы текущие потребители не переписывались за один шаг. «Проход выполнен, но спикеров не найдено» — это `ran` с нулём размеченных сегментов, а не ошибка.

Решение о запуске принимается в одном месте — чистой функцией над тремя входами: список каталожных моделей, доступность нативного рантайма, признак активной записи. Приоритет причин фиксируется тестом. Выбор модели остаётся прежним: только установленная модель задачи диаризации, отсутствующая/качающаяся/повреждённая пропускаются.

Появляется одна операция «диаризовать сохранённую встречу»: читает встречу, прогоняет проход над аудиофайлом встречи, пишет метки в базу, согласует имена спикеров в той же транзакции и эмитит события. Её будут вызывать команда ручного запуска, импорт и перетранскрипция — сама команда становится тонкой обёрткой. Аудио берётся повторным декодированием файла встречи, а не хранением 16-кГц буфера в памяти: буфер больше не нужен ни одному пути.

Проходы сериализуются глобальным мьютексом — одновременно выполняется не более одного. Проверка активной записи выполняется до загрузки модели: при активной записи проход не стартует и возвращает `deferred`, встреча остаётся доступной для ручного запуска. Очереди отложенных задач не появляется.

При успехе эмитится нативное событие обновления транскрипта с идентификатором встречи. Это единственный механизм обновления: страница встречи будет подписываться на него вместо оконного события.

Имя команды остаётся с префиксом audio.cpp: оно называет исполнителя (движок audio.cpp), а не выбранного пользователем провайдера.

## Критерии готовности

- [x] Результат команды ручного запуска несёт статус из пяти значений вместо пары «флаг + текст»
- [x] Отсутствующая модель даёт `no_model`, недоступный рантайм — `no_runtime`, активная запись — `deferred`, исключение прохода — `failed`, успешный проход — `ran`
- [x] `ran` с нулём размеченных сегментов отличим от `failed` и не считается ошибкой
- [x] Решение о запуске принимается одной чистой функцией; приоритет причин зафиксирован тестом
- [x] Установленная модель диаризации выбирается как раньше; отсутствующая, качающаяся и повреждённая не выбираются
- [x] Существует одна операция диаризации сохранённой встречи: метки, согласование имён и события в одном месте
- [x] Проходы не выполняются параллельно — не более одного за раз на процесс
- [x] Проход не запускается во время записи и возвращает `deferred`; встреча остаётся доступной для ручного запуска
- [x] Успешный проход эмитит нативное событие обновления транскрипта с идентификатором встречи
- [x] Удаление модели диаризации не стирает метки из базы
- [x] Rust-тесты покрывают таблицу решений (модель есть/нет, рантайм есть/нет, запись идёт/не идёт) и форму payload события обновления

## Тесты (TDD)

Шов — новая чистая функция решения плюс существующие юнит-тесты выбора модели диаризации и выбора запрошенной модели транскрибации (табличные кейсы «установлена / отсутствует / повреждена / не та задача»). Тесты не должны требовать весов GGUF или нативной библиотеки.

Глобальная сериализация проходов юнит-тестами не покрывается: тест на мьютекс проверял бы реализацию. Проверяется код-ревью и живым прогоном.

## Контекст

- Спека: `.scratch/diarization-provider-decoupling/spec.md` — решения «Модель принятия решения», «Оркестрация», «Статус и события», «Сохранение данных», «Именование».
- Существующая оркестрация прохода и наложения меток уже не зависит от провайдера транскрибации: она берёт только модель задачи диаризации и нативную библиотеку.
- Нативные библиотека и модель диаризации грузятся отдельно от глобального провайдера транскрибации, поэтому выгрузка модели распознавания идущий проход не затрагивает.
- Согласование имён спикеров после прохода обязательно и выполняется в той же транзакции, что и запись меток.
- Тексты сообщений — источник истины в нативном коде.
