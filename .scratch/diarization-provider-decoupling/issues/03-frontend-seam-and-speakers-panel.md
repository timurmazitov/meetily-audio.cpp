# 03: Фронтендовый шов и панель спикеров — ручная диаризация любой встречи

Type: task
Status: resolved
Blocked by: 02

## Что сделать

Снять с фронтенда решение «доступна ли диаризация» и дать пользователю ручной запуск.

Сейчас фронтенд считает, что диаризация доступна только при провайдере `audioCpp`: перед проходом после остановки записи он читает конфигурацию транскрибации и сверяет провайдера. Решение переезжает в нативную сторону (тикет 02), которая одна знает про модель и рантайм. Проверка провайдера и чтение конфигурации удаляются: команда вызывается одинаково для всех провайдеров.

Пустое состояние панели спикеров перестаёт быть текстом-тупиком. Появляется кнопка ручного запуска диаризации: она размечивает любую встречу независимо от того, чем та была транскрибирована, — в том числе записанную до скачивания модели. Кнопка доступна при установленной модели; без модели недоступна с подсказкой скачать модель. Ручной запуск показывает ход выполнения в панели и по завершении обновляет список спикеров либо показывает причину отказа. Причина при явном запуске показывается всегда: это ответ на действие пользователя.

Страница встречи начинает обновляться по нативному событию из тикета 02 вместо оконного события, поэтому фоновый проход может обновить открытую встречу без участия вызвавшего кода. Ручной выстрел оконного события из стоп-флоу удаляется — один механизм вместо двух.

Перезапуск диаризации для уже размеченных встреч в объём не входит.

## Критерии готовности

- [x] Команда диаризации вызывается одинаково при провайдере `localWhisper`, `parakeet` и `audioCpp`
- [x] Проверка провайдера перед проходом и чтение конфигурации транскрибации из стоп-флоу удалены
- [x] Страница встречи обновляет транскрипт по нативному событию; оконное событие больше не используется
- [x] В пустом состоянии панели спикеров есть кнопка ручного запуска
- [x] Без установленной модели кнопка недоступна и объясняет, что нужно скачать модель
- [x] С установленной моделью кнопка доступна; во время выполнения виден индикатор хода, повторное нажатие не запускает второй проход
- [x] После успешного запуска панель показывает полученные метки спикеров
- [x] При отказе панель показывает причину (нет модели / нет рантайма / отложено из-за записи / упало) вместо пустого текста
- [x] Существующий текст-подсказка про модель диаризации не теряется: он остаётся частью пустого состояния
- [x] Тесты фронтендового шва переписаны: вместо «не зовём для Whisper/Parakeet» — «зовём одинаково для всех трёх», плюс молчание на `no_model`/`no_runtime`/`deferred` и тост на `failed`
- [x] Компонентные тесты панели покрывают: наличие кнопки в пустом состоянии, доступность по наличию модели, показ причины отказа, обновление списка после успеха

## Тесты (TDD)

Два существующих шва, новые фреймворки не вводить.

1. Чистые хелперы модуля диаризации — по образцу текущего теста живого стоп-флоу, который инжектит клиент вместо мока Tauri на уровне модуля (у такого мока известна протечка между файлами в одном процессе). Дополнительно таблично проверяется, что константы текстов совпадают с ожидаемыми.
2. Панель спикеров — по образцу существующего компонентного теста панели (react-test-renderer с заменой Radix-компонентов на простые контейнеры), клиент инжектится.
