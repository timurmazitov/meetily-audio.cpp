# 01: Секция «Speaker diarization» в настройках, независимая от провайдера

Type: task
Status: resolved
Blocked by: None (можно начинать сразу)

## Что сделать

Модель диаризации должна быть скачиваемой при любом выбранном провайдере транскрибации.

Сейчас менеджер моделей audio.cpp рендерится в настройках транскрибации только когда выбран провайдер `audioCpp`, поэтому пользователь Whisper или Parakeet физически не может скачать Nemotron-3 Diarization. Расцепить это: менеджер моделей получает параметр задачи модели и переиспользуется как есть — с прогрессом, отменой, удалением и восстановлением состояния с диска.

В настройках появляется постоянно видимая секция «Speaker diarization» с моделью диаризации. Секция не зависит от выбранного провайдера и рендерится при любом из них. Выбор модели в ней не предусмотрен: модель диаризации не транскрибирует, и это уже зафиксировано существующим контрактом менеджера.

Если диагностическая команда модуля audio.cpp сообщает, что нативная библиотека недоступна, секция показывает предупреждение о недоступности движка диаризации с текстом ошибки в подсказке. Карточка модели при этом остаётся скачиваемой: пользователь может подготовить модель заранее, а предупреждение объясняет, почему проход не запустится сейчас.

Секция моделей распознавания внутри провайдера `audioCpp` не меняется.

## Критерии готовности

- [x] Секция «Speaker diarization» видна в настройках при провайдере `localWhisper`, `parakeet` и `audioCpp`
- [x] В секции рендерится только модель задачи диаризации; модели распознавания в ней не появляются
- [x] Скачивание, отмена, удаление и повторное скачивание модели работают из этой секции; прогресс и состояние переживают перезапуск приложения
- [x] Модель диаризации нельзя выбрать как модель транскрибации — выбор в секции недоступен
- [x] При недоступной нативной библиотеке секция показывает предупреждение, а карточка модели остаётся скачиваемой
- [x] При доступной нативной библиотеке предупреждения нет
- [x] Секция моделей распознавания внутри провайдера `audioCpp` ведёт себя как раньше
- [x] Компонентные тесты менеджера покрывают: фильтрацию по задаче модели, наличие и отсутствие предупреждения о рантайме, сохранение доступности карточки при недоступном рантайме
