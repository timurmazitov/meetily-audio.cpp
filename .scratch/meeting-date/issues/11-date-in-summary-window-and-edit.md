# 11: Дата встречи в окне саммари и её правка

Type: task
Status: resolved
Blocked by: 06

## Что сделать

Дата встречи переезжает из шапок обеих панелей в окно с текстом саммари, и её
можно исправить вручную.

- Строка даты убирается из шапки панели транскрипта и из шапки панели саммари.
- В окне с текстом саммари дата стоит в правом верхнем углу: элемент `<h3>`,
  серый (`text-gray-500`), прижата вправо, не прокручивается вместе с текстом.
- Дата показывается только когда есть текст саммари; в пустом состоянии её нет.
- Окно редактирования названия встречи получает второе поле —
  `datetime-local` «Meeting Date and Time». Одна кнопка Save сохраняет название и
  дату одной операцией.
- Сохранённая дата сразу видна в сайдбаре (строка и порядок списка) и в открытой
  встрече.

Ограничения: дата встречи — это `recorded_at` (GLOSSARY: «дата встречи»), не
`created_at`; неизвестная дата остаётся `NULL` и никогда не подменяется «сейчас»
(ADR-0005). Файлы записи на диске не переименовываются, саммари не
перегенерируется.

## Критерии готовности

- [x] В шапках панелей нет строки даты.
- [x] В окне саммари дата в правом верхнем углу, серым, не уезжает при прокрутке.
- [x] Встреча без саммари даты в углу не показывает.
- [x] В диалоге правки есть поле даты и времени; Save пишет оба поля.
- [x] После сохранения дата обновилась в открытой встрече и в списке, список
      пересортирован.
- [x] Очистка поля делает дату снова неизвестной.
- [x] Тесты зелёные.

## Comments

- Контракт: `api_save_meeting_title` получил необязательный `recordedAt` — три
  состояния: `null`/отсутствие = «только переименовать, дату не трогать»,
  `""` = «стереть дату», RFC3339 = «записать момент». Диалог отправляет дату
  только если поле реально изменилось, иначе чистое переименование урезало бы
  хранимые секунды до минут.
- Репозиторий: `update_meeting_title_and_date` — одна транзакция; старая
  `update_meeting_title` оставлена тонкой обёрткой над ней.
- Живое обновление открытой встречи: `window.dispatchEvent(new CustomEvent(
  'meeting-metadata-updated', { detail: { meetingId } }))` из сайдбара,
  слушатель в `page.tsx` дёргает `refetch()` из `usePaginatedTranscripts`.
- `useMeetingData.updateMeetingTitle` больше не пересобирает строку списка
  (`{ id, title }` → `{ ...m, title }`): иначе авто-переименование из саммари
  стирало дату и длительность в сайдбаре.
- Форматер: общий `formatMeetingDateTime` (`18/11/2026, 14:32`) и две новые
  функции-моста `toDateTimeInputValue` / `fromDateTimeInputValue` в
  `lib/meeting-datetime.ts`; несуществующие дни и невозможное время отвергаются,
  а не переносятся.
- Проверка: `cargo test --lib` — **677 passed / 0 failed / 7 ignored**;

  baseline mock-isolation (`logo-doodle`, `recording-controls-stop`,
  `recording-state-shutdown`, `onboarding-context-completion`), каждый файл
  зелёный отдельно. Тесты тикета: `panel-meeting-date` 7/7,
