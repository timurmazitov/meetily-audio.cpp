# 04: Старые встречи получают дату и длительность

Type: task
Status: ready-for-agent
Blocked by: 02

## Что сделать

Идемпотентный проход при старте приложения заполняет новые поля у встреч, созданных до миграции. Пишет только в пустые поля: частично заполненную строку не перезаписывает целиком.

1. Встречи с папкой записи и существующим `metadata.json`: дата из `created_at` файла, длительность из файла.
2. Оставшиеся без даты: `recorded_at = created_at`.
3. Оставшиеся без длительности: `MAX(audio_end_time)` по транскриптам встречи.
4. Нет транскриптов — оставить `NULL`.

Проход не блокирует старт UI и не логирует содержимое встреч — только агрегированные счётчики.

Ограничения: приблизительность даты и длительности для старых встреч принимается осознанно — точное значение взять негде.

## Критерии готовности

- [ ] Запускаю приложение на базе со старыми встречами — в списке у них появляются дата и длительность.
- [ ] Повторный запуск не меняет уже заполненные значения.
- [ ] Строка с заполненной датой и пустой длительностью досчитывает только длительность.
- [ ] Встреча без папки записи и без транскриптов получает дату из `created_at` и остаётся без длительности.
- [ ] Битый `metadata.json` не ломает проход.
- [ ] Тесты бэкфилла зелёные.
