# Спецификация: дата и длительность встречи

Status: implemented (2026-11-18). Branch `feature/meeting-date`.

Термины — по `GLOSSARY.md`: дата встречи, длительность встречи. Контекст решений — ADR-0005 (дата встречи отделена от `created_at`), ADR-0003 (настраиваемый системный промпт).

Работа разбита на тикеты в `issues/` — вертикальными срезами, каждый даёт наблюдаемый в продукте результат.

## Problem Statement

Ни дата проведения встречи, ни её длительность не отображаются нигде: список «Meeting Notes» показывает только название, экран встречи — только кнопки.

Причины лежат глубже вёрстки:

- **Семантика даты потеряна.** В таблице `meetings` единственная временная метка `created_at` заполняется `Utc::now()` в момент вставки строки. Для записи это время **после** остановки, для импорта — момент импорта. Различить «когда встреча состоялась» и «когда строка появилась в базе» невозможно.
- **Длительности в базе нет вообще.** Точные значения существуют только вне БД: `metadata.json` в папке записи (`created_at` пишется в момент старта, `duration_seconds` — при сохранении) и длительность исходного файла при импорте. Всё это приложение выбрасывает.
- **Список не получает данных.** Команда списка режет ответ до `{ id, title }`, поэтому строка сайдбара не имеет ни даты, ни длительности.
- **Место для даты не существует.** Шапки панелей саммари и транскрипта — это центрированные строки кнопок; «правого верхнего угла» как места для элемента нет.
- **Модель не знает дату.** Финальное пользовательское сообщение содержит только транскрипт и дополнительный контекст. При этом несколько bundled-шаблонов **прямо просят у модели дату** (секция `Date` в `daily_standup`, `Meeting Date & Time` в `project_sync`, аналогично в `psychatric_session`, `sales_marketing_client_call`, `retrospective`) — то есть в отчёте либо «None noted in this section», либо **выдуманная дата**.

## Solution

Дата встречи и длительность становятся явными данными: две необязательные колонки, заполняемые в точках создания встречи и бэкфиллящиеся для существующих строк. Список получает их и показывает второй строкой под названием; название ограничено двумя строками с троеточием. В шапках панелей появляется тонкая строка с датой, прижатая вправо. Копирование и экспорт переходят на дату встречи. Модель получает дату отдельным блоком в пользовательском сообщении, а шаблоны учат её брать оттуда.

Порядок работ — вертикальными срезами: сначала запись, затем импорт, затем остальные поверхности. Записанная встреча, показанная с датой и длительностью в списке, — первый демонстрируемый результат.

## User Stories

1. Как пользователь, я хочу, чтобы у записанной встречи датой считался момент начала записи, чтобы часовой созвон не датировался временем окончания.
2. Как пользователь, я хочу, чтобы у импортированной встречи датой считался момент импорта, чтобы дата всегда была достоверной.
3. Как пользователь, я хочу видеть в списке дату и длительность каждой встречи, чтобы отвечать на вопрос «когда и сколько» не открывая встречу.
4. Как пользователь, я хочу, чтобы длинные названия обрезались троеточием после двух строк, чтобы список не превращался в рваную простыню.
5. Как пользователь, я хочу, чтобы отсутствующие дата и длительность не показывались, чтобы не видеть `0 min` и выдуманные даты.
6. Как пользователь, я хочу, чтобы у старых встреч дата и длительность тоже были заполнены, чтобы половина списка не жила с пустыми значениями.
7. Как пользователь, я хочу, чтобы список шёл в хронологии состоявшихся встреч, чтобы старый импорт не оказывался наверху только потому, что его импортировали сегодня.
8. Как пользователь, я хочу видеть дату в правом верхнем углу панели открытой встречи, чтобы ориентироваться в ней.
9. Как пользователь, я хочу видеть ту же дату в обеих панелях, чтобы при переключении вкладок она не исчезала.
10. Как пользователь, я хочу, чтобы скопированное и экспортированное саммари содержали ту же дату, что и экран.
11. Как пользователь, я хочу, чтобы модель знала дату встречи, чтобы относительные формулировки в транскрипте трактовались в правильной хронологии.
12. Как пользователь шаблона с секцией даты, я хочу, чтобы дата в отчёте была настоящей.
13. Как пользователь, я хочу, чтобы дата доходила до модели независимо от моего собственного системного промпта.
14. Как пользователь, я хочу, чтобы переключение языка саммари не показывало закэшированное саммари без даты.
15. Как пользователь локальной модели на длинном транскрипте, я хочу, чтобы промежуточные проходы не тратили контекст на дату.
16. Как разработчик, я хочу один общий форматер и один источник значения даты, чтобы поверхности не разъехались.
17. Как разработчик, я хочу, чтобы `created_at` остался неизменным аудит-полем.
18. Как разработчик, я хочу, чтобы отсутствие значения выражалось `NULL`, а не нулём или подставленным «сейчас».
19. Как разработчик, я хочу, чтобы бэкфилл был идемпотентным.
20. Как разработчик, я хочу, чтобы контракты команд расширялись аддитивно, без ломающих изменений.

## Implementation Decisions

- **Миграция** `20261119000000_add_meeting_recorded_at_and_duration.sql`: `ALTER TABLE meetings ADD COLUMN recorded_at TEXT` и `ADD COLUMN duration_seconds REAL`. Обе nullable, без `DEFAULT`. `NULL` — «неизвестно», не ноль.
- **`created_at` не переопределяется** ни по смыслу, ни по значениям: это по-прежнему момент появления строки.
- **Путь записи**: `recorded_at` и `duration_seconds` берутся из `metadata.json` в папке встречи (файл пишет сам `recording_saver`: `created_at` — в момент старта, `duration_seconds` — при сохранении). Если файла нет или значение не разбирается — `duration_seconds` из конца последнего сегмента, `recorded_at` = текущий момент; если нет и этого — `NULL`. Порядок «`metadata.json` записан ↔ сохранение в БД» при реализации проверить; фолбэк делает результат корректным в любом порядке.
- **Путь импорта**: `recorded_at` = момент импорта, `duration_seconds` = длительность декодированного файла (уже вычисляется в процессе импорта).
- **Чтение**: `api::Meeting` получает `recorded_at` (RFC3339) и `duration_seconds`, оба `skip_serializing_if = "Option::is_none"`. `MeetingDetails` и `MeetingMetadata` — то же, аддитивно.
- **Порядок списка**: `ORDER BY COALESCE(recorded_at, created_at) DESC` — встреча без даты не уезжает в конец.
- **Бэкфилл** — идемпотентный проход при старте, только в пустые поля: (1) из `metadata.json`; (2) `recorded_at = created_at` для оставшихся; (3) `duration_seconds = MAX(audio_end_time)` для оставшихся; (4) нет транскриптов — `NULL`. Приблизительность для старых встреч принимается осознанно.
- **Форматеры (TS)** — новый модуль: `formatMeetingDateTime` → `18/11/2026, 14:32` (локальное время, 24 часа, ведущие нули; значение без времени даёт только дату; нет значения → `null`), `formatMeetingDuration` → `< 1 min` / `42 min` / `1 h 23 min` (нет значения или `0` → `null`). **Не** переиспользуют `resolveMeetingDate`, потому что тот подставляет текущий момент — для отображения это ложь.
- **Строка списка**: название `line-clamp-2` вместо `break-words`; под ним `text-xs text-gray-500` с текстом `дата · длительность`, пропуская отсутствующие части и не рисуясь вовсе, если нет обеих. Блок поискового совпадения `Match:` остаётся **под** этой строкой. Свёрнутый сайдбар правок не требует — строки в нём не рендерятся.
- **Шапки панелей**: отдельная тонкая строка `flex items-center justify-end` над существующей центрированной строкой кнопок; компоновка кнопок не меняется. Правило одинаково для панели саммари и панели транскрипта. Только дата и время, без длительности.
- **Копирование и экспорт**: источником становится дата встречи, а не `created_at`. Формат в документе не меняется — это отдельный, уже принятый формат.
- **Промпт**: `<meeting_date>18/11/2026, 14:32</meeting_date>` в начале пользовательского сообщения финального прохода, до `<transcript_chunks>`. **Не** плейсхолдер в системном промпте: базовый промпт редактируется пользователем, а шаблонный перекрывает его полностью, поэтому плейсхолдер молча отключил бы дату у всех, кто сохранил свой текст.
- **Значение читает Rust** из записи встречи в базе внутри фоновой обработки саммари; контракт `api_process_transcript` не меняется. Нет даты — блока нет; подстановка текущего момента запрещена.
- **Область промпта**: только финальный проход. Чанк-саммари, комбайн, перевод и нормализация дату не получают.
- **Шаблоны-потребители**: инструкции секций с датой переводятся на явное «возьми дословно из `<meeting_date>`; если блока нет — не выдумывай». Дефолтный базовый системный промпт **не** правится — правка не долетит до пользователей с сохранённым промптом.
- **Кэш**: источник кэша получает дату с `serde(default)`, иначе ранее сохранённые записи перестанут десериализоваться. Текущий момент в fingerprint не добавляется.
- **Заголовок саммари** (`# <Title>`) остаётся без даты: он перезаписывает имя встречи в базе.
- **Уже сохранённые саммари** с выдуманной датой не перегенерируются — дата станет верной при следующей регенерации.

## Testing Decisions

- Тесты проверяют наблюдаемое поведение на швах: что лежит в строке после сохранения/импорта, что возвращает команда, какой текст уходит на вход генерации, что видит пользователь. Внутренние детали чтения файлов и сборки промпта не тестируются.
- Швы по слоям: миграции на старой базе; сохранение/импорт заполняют поля верными значениями; бэкфилл идемпотентен и не затирает заполненное; список сортирует по дате встречи; форматтеры и их края; строка сайдбара и шапки панелей; копирование/экспорт используют дату встречи; финальный промпт содержит блок, а чанк/комбайн — нет; источник кэша различается по дате и читает старые записи.
- Проверка на живом LLM-провайдере не автоматизируется — один ручной прогон на `daily_standup`.

## Out of Scope

- Локализация интерфейса: строки длительности остаются английскими (`min`, `h`), как и весь UI.
- Группировка списка по датам («Сегодня», «Вчера»).
- Дата из метаданных импортируемого файла (дата съёмки): для импорта датой считается момент импорта.
- Плейсхолдер `{meeting_date}` для системного промпта и его документирование в подсказке настроек.
- Название встречи и длительность в контексте модели.
- Автоматическая перегенерация существующих саммари.
- Правка дефолтного базового системного промпта.
- Показ даты где-либо ещё: настройки, диалог импорта, страница заметок.

## Further Notes

- Второй форматер того же формата появится в Rust для промпта. Дублирование осознанное: тридцать символов дешевле, чем протаскивание отформатированной строки через бэкенд. Оба зафиксированы тестами на одну и ту же строку.
- Правка bundled-шаблонов не меняет уже скопированные пользовательские копии (приоритет у папки пользователя) — упомянуть в release notes.
- Разбор `metadata.json` в Rust уже существует для нужд саммари; переиспользуется стиль чтения, новый формат файла не вводится.

## Comments

Реализовано в ветке `feature/meeting-date`; все десять тикетов закрыты (`Status: resolved`), каждый со своим `## Comments`.

Прогон код-ревью (две оси — стандарты и спека) нашёл восемь пунктов, все исправлены отдельным проходом:

- сохранение записи больше не пишет нулевую длительность (`usable_duration_seconds` применён и к фолбэку из последнего сегмента);
- предикат «пригодной длины» сведён в одну функцию в Rust (`database/meeting_facts.rs`), три места ссылаются на неё;
- чтение `metadata.json` при сохранении записи вынесено в `spawn_blocking` до открытия транзакции (AGENTS.md: не блокировать async);
- дата встречи больше не пишется в журнал — только «включена/отсутствует»;
- `MeetingDetails` дополнен `recorded_at`/`duration_seconds` (спека требовала аддитивно, тикет 02 расширил только `MeetingMetadata`);
- легаси-ветка экспорта саммари берёт дату встречи с фолбэком на `created_at`;
- разбор значения без времени (`DATE_ONLY` + проверка переполнения) сведён в один `parseDateOnly` в `meeting-date.ts`;
- противоречие ADR-0005 со спекуляцией фолбэка записи разрешено в пользу спеки, исключение записано в ADR.

Осознанно не менялось: `retrospective` просит диапазон спринта, а не дату встречи, поэтому формулировка «дословно из блока» к нему не применена — вместо этого инструкция прямо говорит, что блок не заменяет диапазон.

Проверка: `cargo test --lib` — **672 passed / 0 failed / 7 ignored**; `bun test` — **319 pass / 12 fail**, все 12 — известный baseline `mock.module` (`logo-doodle`, `recording-controls-stop`, `recording-state-shutdown`), сверено с замером на `main` до начала работы; `tsc --noEmit` — exit 0.

Не проверено: живые прогоны в Tauri-приложении (запись со стопом, импорт, бэкфилл на старой базе, копирование/экспорт, узкое окно панелей) и один ручной прогон на живом LLM-провайдере с шаблоном `daily_standup` — по спеке это ручные проверки. Строка для release notes о том, что уже скопированные пользовательские копии шаблонов правку не получат, записана в `frontend/src-tauri/templates/README.md`; сам пункт release notes пишется при публикации.
