# 07: Выживание имён при пересчёте меток

Type: task
Status: resolved
Blocked by: 02

## Что сделать

Не терять имена при повторной диаризации, импорте и ретранскрипции, когда результат не изменился.

После записи новых меток во всех трёх путях:

1. импорт — `frontend/src-tauri/src/audio/import.rs:685`;
2. ретранскрипция (с `DELETE FROM transcripts` на `retranscription.rs:527`) — `frontend/src-tauri/src/audio/retranscription.rs:485`;
3. постзаписная диаризация — `frontend/src-tauri/src/audio/diarization_commands.rs:85`;

выполнить общую функцию сверки привязок (одна реализация в `speaker.rs`, чтобы три пути не разъехались):

- сравнить `DISTINCT speaker` встречи с набором `meeting_speakers.label`;
- удалить привязки меток, которых больше нет, и осиротевшие записи справочника;
- если набор совпал — имена остаются как были;
- если ни одна прежняя метка не сохранилась — удалить все привязки встречи;
- при сбросе имён из-за полной смены набора отправить событие, которое UI показывает как хинт «имена спикеров сброшены, потому что голоса пересчитаны» (в стиле существующего `diarization-unavailable`).

Автоматического сопоставления по голосу нет: эмбеддингов в проекте не существует. Правки отдельных строк (`api_set_transcript_speaker`) при пересчёте законно теряются вместе с метками.

## Тесты (TDD)

Инлайн `#[cfg(test)]` рядом со сверкой:

- неизменный набор меток → имена сохраняются;
- набор вырос (`speaker_0` → `speaker_0..speaker_1`) → старое имя остаётся, новая метка без имени;
- набор уменьшился → привязка исчезнувшей метки удалена, остальные сохранены;
- полная смена (`speaker_0..1` → `speaker_4..5`) → все привязки удалены, событие сброса отправлено;
- транскрипт без меток → привязок нет, ошибок нет.
