# Спецификация: имена спикеров

Status: implemented (2026-11-17). Branch `feature/speaker-names`.

Термины — по `GLOSSARY.md`: «диаризация», «спикер», «имя спикера». Текущее поведение диаризации описано в `docs/architecture.md`.

## Problem Statement

Диаризация присваивает репликам безличные метки `speaker_0`, `speaker_1` по порядку появления. В UI они показываются как `Speaker 1`, `Speaker 2`, а в копировании и экспорте — как сырое `speaker_0:` / `speaker_1:` (`frontend/src/lib/transcript-format.ts:53`), то есть пользователь видит две разные подписи одного и того же и не может заменить их реальными именами. В БД нет ни таблицы имён, ни команды переименования, ни способа исправить неверно атрибутированную реплику. Имена спикеров не попадают ни в саммари, ни в поиск.

## Solution

Появляется глобальный справочник людей и связь «спикер встречи ↔ человек». Пользователь открывает панель **Speakers** на странице встречи, для каждого спикера выбирает существующего человека из справочника или создаёт нового, сохраняет по **Done**. Отдельно у каждой реплики транскрипта есть дропдаун для немедленной правки одной строки. Имена используются в транскрипте, в копировании, в экспорте и в новых саммари.

Переименований нет нигде: имя в справочнике неизменно, правка опечатки выполняется как отвязка от встреч и создание имени заново. Автоматического узнавания людей между встречами нет — эмбеддингов голоса в проекте не существует; связь «встреча ↔ человек» ставится только вручную.

## User Stories

1. Как пользователь, я хочу видеть в транскрипте имена людей вместо `Speaker 1`, чтобы понимать, кто что сказал.
2. Как пользователь, я хочу открыть панель Speakers, чтобы увидеть всех спикеров этой встречи и число их реплик.
3. Как пользователь, я хочу выбрать для спикера уже существующего человека из справочника, чтобы один и тот же человек не заводился дважды.
4. Как пользователь, я хочу создать нового человека прямо в панели, чтобы назвать спикера, которого ещё нет в справочнике.
5. Как пользователь, я хочу видеть при вводе имени совпадения из справочника, чтобы выбрать существующую запись вместо создания дубля.
6. Как пользователь, я хочу, чтобы точное совпадение имени (без учёта регистра) выбирало существующего человека, а не создавало второго.
7. Как пользователь, я хочу сохранять имена панелью по кнопке Done, чтобы подготовить все имена и записать их одним действием.
8. Как пользователь, я хочу, чтобы закрытие панели или Escape отбрасывали несохранённые имена, чтобы случайно не записать недоделанное.
9. Как пользователь, я хочу исправить спикера у одной реплики через её дропдаун, чтобы не переименовывать всех.
10. Как пользователь, я хочу снять имя со спикера, чтобы вернуть состояние «имя не задано».
11. Как пользователь, я хочу снять атрибуцию реплики («No speaker»), чтобы шумная или ошибочная реплика не приписывалась человеку.
12. Как пользователь, я хочу, чтобы два спикера одной встречи нельзя было сопоставить одному человеку, чтобы не получить необратимое слияние.
13. Как пользователь, я хочу видеть в копировании и экспорте те же подписи, что и в транскрипте, чтобы файл не расходился с UI.
14. Как пользователь, я хочу, чтобы при отсутствии имени оставалась подпись `Speaker N`, чтобы транскрипт был читаем без обязательного наименования.
15. Как пользователь, я хочу, чтобы новые саммари учитывали имена спикеров, чтобы модель писала «Алекс решил», а не «спикер сказал».
16. Как пользователь, я хочу, чтобы при перезапуске диаризации с тем же результатом имена сохранялись, чтобы не вводить их заново.
17. Как пользователь, я хочу получить явное сообщение, когда имена сброшены из-за изменившегося набора спикеров, чтобы не считать пустые имена ошибкой.
18. Как пользователь, я хочу, чтобы кнопка Speakers была доступна и без диаризации, чтобы понять причину отсутствия спикеров.
19. Как пользователь Whisper/Parakeet, я хочу, чтобы легаси-транскрипты без спикеров копировались и экспортировались ровно как раньше.
20. Как разработчик, я хочу, чтобы `transcripts.speaker` оставался меткой диаризации, а имя резолвилось отдельно, чтобы существующие контракты Tauri-команд и события не ломались.
21. Как разработчик, я хочу тесты на резолв имени и формат подписи, чтобы регрессии ловились без ручной проверки UI.
22. Как разработчик, я хочу тесты миграции на существующей базе, чтобы старые транскрипты открывались без изменений.

## Implementation Decisions

### Данные

Две таблицы (миграция `frontend/src-tauri/migrations/20261118000000_add_speaker_names.sql`):

```sql
CREATE TABLE speakers (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
CREATE UNIQUE INDEX idx_speakers_name ON speakers(name COLLATE NOCASE);

CREATE TABLE meeting_speakers (
    id TEXT PRIMARY KEY,
    meeting_id TEXT NOT NULL,
    label TEXT NOT NULL,
    speaker_id TEXT NOT NULL,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    FOREIGN KEY (meeting_id) REFERENCES meetings(id) ON DELETE CASCADE,
    FOREIGN KEY (speaker_id) REFERENCES speakers(id) ON DELETE CASCADE
);
CREATE UNIQUE INDEX idx_meeting_speakers_label ON meeting_speakers(meeting_id, label);
CREATE UNIQUE INDEX idx_meeting_speakers_person ON meeting_speakers(meeting_id, speaker_id);
```

- `speakers.name` глобально уникален без учёта регистра (`COLLATE NOCASE`). Двух разных людей с одним именем завести нельзя; различимые люди получают различимые имена.
- Строка `meeting_speakers` существует, только пока имя задано. «Без имени» = удаление строки, поэтому `speaker_id NOT NULL` и каскадное удаление не оставляют мусора.
- `transcripts.speaker` не меняется: это по-прежнему безличная метка `speaker_N` (`frontend/src-tauri/src/audio/transcription/diarization.rs:94`). Имя — отдельная сущность (см. «спикер» и «имя спикера» в `GLOSSARY.md`).
- Список спикеров встречи не хранится: это `DISTINCT speaker` по `transcripts` c `LEFT JOIN` на `meeting_speakers` и `speakers`. Так он не расходится с фактическими метками.
- Учитываются только метки вида `speaker_N`. Значения `mic`/`system` из устаревшего комментария миграции `20251110000001_add_speaker_field.sql` и любые свободные строки в панель и дропдаун не попадают — как и сейчас в чипе (`frontend/src/components/VirtualizedTranscriptView.tsx:50`).

### Команды (Tauri)

- `api_get_meeting_speakers(meeting_id)` → `[{label, speaker_name, segment_count, first_start_time, top_speaker_names}]`. Нужен панели: у пагинированного транскрипта в памяти только одна страница, поэтому набор спикеров из загруженных сегментов не вывести. `top_speaker_names` — ограниченный список имён справочника для подсказок (см. ниже).
- `api_assign_meeting_speakers(meeting_id, assignments)` — пакетное назначение из **Done**: `[{label, name}]`, где `name: null` означает «снять имя», а непустое имя — «привязать к существующему или создать нового».
- `api_set_transcript_speaker(transcript_id, label | null)` — немедленная правка одной строки; `null` = «No speaker». Затрагивает только эту реплику, `meeting_speakers` не меняет.
- `api_get_speaker_names(query, limit)` → `[{id, name, meeting_count}]` — справочник для подсказок в поле выбора.
- Аддитивное поле `speaker_name: Option<String>` в `MeetingTranscript` (`frontend/src-tauri/src/api/api.rs:132`), чтобы экспорт и саммари не делали join на фронте. Существующие поля и их отсутствие в JSON не меняются.

### Правила ввода имени

- Сравнение — `trim` + `NOCASE`. Внутренние пробелы сохраняются как есть. Регистр первого ввода сохраняется для отображения.
- Точное совпадение = выбор существующего человека; пункт «Создать» в этом случае не показывается, поэтому дубль технически невозможен.
- Длина 1–100 символов после `trim`. Пустое имя недопустимо (снятие имени — отдельное действие «Без имени»).
- Перепривязка спикера к другому человеку разрешена — это выбор, а не переименование.
- Два спикера одной встречи на одного человека блокируются с сообщением вида «этот человек уже сопоставлен спикеру Speaker 1». Слияние (merge) не реализуется.
- Запись справочника, на которую больше не ссылается ни одна встреча, удаляется в той же транзакции. Переименования записи нет; исправление опечатки = отвязать везде и создать имя заново.
- `meetings.updated_at` поднимается при изменении имён — как при переименовании заголовка (`frontend/src-tauri/src/database/repositories/meeting.rs:187`).

### Поведение при пересчёте меток

Пересчёт выполняется в трёх местах: импорт (`frontend/src-tauri/src/audio/import.rs:685`), ретранскрипция (`frontend/src-tauri/src/audio/retranscription.rs:485`, с предварительным `DELETE FROM transcripts`), постзаписная диаризация (`frontend/src-tauri/src/audio/diarization_commands.rs:85`).

- После записи новых меток сравнивается набор `DISTINCT speaker` встречи с набором `meeting_speakers.label`.
- Метки, которых больше нет, удаляются вместе с их привязками.
- Если набор меток совпал — имена сохраняются без изменений.
- Если набор изменился настолько, что ни одна прежняя метка не сохранилась, все привязки встречи удаляются, а UI показывает хинт «имена спикеров сброшены, потому что голоса пересчитаны».
- Угадывания по порядку появления нет: эмбеддингов голоса в проекте не существует.

### UI

- Кнопка **Speakers** в `frontend/src/components/MeetingDetails/TranscriptButtonGroup.tsx` (иконка + подпись, скрытая на узкой ширине, как у соседних кнопок). Кнопка видна всегда; если меток нет, панель открывается пустой с подсказкой про модель диаризации. Бета-флага нет.
- Панель — правый `Sheet` (`frontend/src/components/ui/sheet.tsx`), транскрипт остаётся виден: пользователь сверяет имена со строками.
- Для каждого спикера: подпись-заглушка (`Speaker 1`), число реплик и одно поле выбора. Печатаешь — видны совпадения из справочника; если точного совпадения нет, первой строкой идёт «Создать „Мария“»; первым пунктом списка — «Без имени». Реализация — Popover + `Command` по образцу `frontend/src/components/ModelSettingsModal.tsx:897`.
- Кнопки **Done** и **Cancel**; Escape и клик вне панели отменяют несохранённые изменения. Кнопки Listen нет.
- Дропдаун у реплики в `frontend/src/components/VirtualizedTranscriptView.tsx`: только спикеры этой встречи плюс «No speaker», сохранение немедленное.
- Чип спикера показывает имя, если оно задано, иначе `Speaker N`. Номер берётся из суффикса метки, а не из порядка в загруженной странице.
- Все строки — английские литералы на месте, как в остальном проекте: i18n в проекте нет.

### Текст

- Копирование и экспорт (`frontend/src/lib/transcript-format.ts`): `[00:00–00:24] Alex: …`; без имени — `[00:00–00:24] Speaker 1: …`; сегмент без метки — без префикса спикера. Сырое `speaker_N` из файла исчезает.
- Если ни у одного сегмента нет метки, формат остаётся байт-в-байт прежним (`[MM:SS] text`).
- Саммари (`frontend/src/hooks/meeting-details/useSummaryGeneration.ts:387`): `[MM:SS] Alex: text`. Кэш саммари инвалидируется сам, потому что fingerprint считается по итоговому тексту (`frontend/src-tauri/src/summary/service.rs:131`). Существующие саммари не перегенерируются автоматически.

## Testing Decisions

Хороший тест проверяет внешнее поведение — какой текст видит пользователь и какие строки появляются в БД — и не привязан к внутренней структуре компонентов.

- **Миграция (Rust, `frontend/src-tauri/src/database/migrations_tests.rs`)**: миграция применяется к базе со старыми транскриптами без имён; старые строки открываются без изменений; `UNIQUE (meeting_id, label)`, `UNIQUE (meeting_id, speaker_id)` и глобальный `NOCASE`-уникальный `speakers.name` действительно срабатывают.
- **Репозиторий (Rust)**: назначение имени создаёт запись справочника и привязку; повторное назначение того же имени использует существующую запись; «Без имени» удаляет привязку и затем сироту; назначение двух спикеров одному человеку возвращает ошибку; пересчёт с неизменным набором меток сохраняет имена, с изменившимся — удаляет.
- **Формат (bun:test, `frontend/tests/lib/transcript-format.test.ts`)**: текущие ожидания `[00:00–00:24] speaker_0: …` осознанно заменяются на именованный вариант; отдельные кейсы на «без имени», «без метки» и на неизменный легаси-формат без спикеров.
- **Чип и дропдаун (bun:test, `frontend/tests/components/diarization-speaker-labels.test.tsx`)**: чип показывает имя вместо `Speaker N`; без имени — `Speaker N`; `mic`/`system`/свободные строки не рендерятся; дропдаун содержит спикеров встречи и «No speaker».
- **Панель (bun:test, `frontend/tests/components/`)**: выбор существующего имени, создание нового, блокировка второго спикера на того же человека, отмена по Escape, пустое состояние без меток.

## Out of Scope

- Merge duplicate speakers (слияние дубликатов).
- Прослушивание голоса (**Listen**) — отдельная задача; turns диаризации в БД не сохраняются.
- Ожидаемое число участников (**Auto / 1–10**) и **Re-run**: `diarize()` в движке не принимает число спикеров (`frontend/src-tauri/src/audio_cpp_engine/engine.rs:80`).
- Переименование и слияние записей глобального справочника, управление справочником в настройках.
- Автоматическое узнавание людей между встречами (эмбеддинги голоса).
- Поиск реплик по человеку, FTS/векторный поиск: текущий поиск — `LIKE '%query%'` по тексту (`frontend/src-tauri/src/database/repositories/transcript.rs:93`) без колонки `speaker`. Схема этой задачи такую возможность не блокирует.
- Перегенерация существующих саммари при смене имён.

## Further Notes

- `transcripts.json` в папке записи (`frontend/src-tauri/src/audio/common.rs:159`) остаётся write-only артефактом; источник правды — SQLite. Новые поля в него не добавляются.
- `GLOSSARY.md` дополняется термином «имя спикера»; определение «спикера» не меняется.
- Порядок тикетов: `01` → `02` → (`03`, `04`, `05`, `06`, `07`). `03` и `04` не трогают БД и могут идти параллельно с `05`/`06`.
