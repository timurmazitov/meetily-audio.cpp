# Полное удаление Usage Analytics (PostHog)

Status: ready-for-agent

Исследование: [docs/research/remove-usage-analytics.md](../../../docs/research/remove-usage-analytics.md) — там полный список файлов, точек вызова и номеров строк.

## Problem Statement

Приложение содержит функционал Usage Analytics: сбор событий использования
(страницы, кнопки, записи встреч, транскрибация, саммари, настройки) и отправку
их в PostHog Cloud (`https://us.i.posthog.com`) через Rust-ядро на `posthog-rs`.
API key PostHog захардкожен в коде. Пользователь хочет, чтобы приложение
вообще ничего не собирало и никуда не отправляло, и чтобы в интерфейсе не было
никаких упоминаний об аналитике.

## Solution

Полностью вырезать механизм аналитики из всех слоёв приложения: Rust-ядро
(клиент PostHog, Tauri-команды, регистрация команд), TS-клиент-обёртку,
React-провайдер и компоненты согласия, все ~25 точек вызова трекинга,
аналитические тесты и зависимость `posthog-rs`. После изменения приложение
не содержит кода, способного собирать или отправлять usage-события, и в UI
нет разделов/текстов об аналитике. Захардкоженный PostHog API key
отзывается/ротируется в кабинете PostHog (вне кода).

## User Stories

1. Как пользователь, я хочу, чтобы приложение не отправляло никаких событий использования на внешние серверы, чтобы мои действия не отслеживались.
2. Как пользователь, я не хочу видеть в интерфейсе разделов, переключателей и текстов про Usage Analytics, чтобы не путаться в настройках.
3. Как пользователь, я хочу, чтобы при старте приложения не выполнялось сетевых запросов к сервисам аналитики, чтобы не расходовать трафик и не палить активность.
4. Как пользователь, я хочу, чтобы удаление встречи, запись, транскрибация и генерация саммари не порождали никаких скрытых событий, чтобы мои данные о встречах оставались локальными.
5. Как пользователь, я хочу, чтобы устаревший локальный файл `analytics.json` перестал использоваться, чтобы в системе не осталось «аналитических» остатков.
6. Как мейнтейнер, я хочу удалить зависимость `posthog-rs` и весь модуль `analytics` из Rust-ядра, чтобы уменьшить поверхность кода и атаки.
7. Как мейнтейнер, я хочу, чтобы API key PostHog был отозван, так как он засвечен в истории репозитория.
8. Как мейнтейнер, я хочу, чтобы сборка и существующие тесты проходили после удаления, чтобы регрессий не было.
9. Как мейнтейнер, я хочу, чтобы внутренняя диагностика (audio pipeline stats, notification statistics, transcription segments) не пострадала, так как она не является Usage Analytics.

## Implementation Decisions

- **Rust core**: удалить модуль `analytics` целиком (клиент `AnalyticsClient`,
  все Tauri-команды трекинга, глобальный статик клиента). Из регистрации
  `invoke_handler` в `lib.rs` убрать все ~25 аналитических команд. Из
  `Cargo.toml` убрать `posthog-rs`, обновить `Cargo.lock`. Общие крейты
  (`uuid`, `chrono`, `serde`, `tokio`, `log`) не трогать — используются другими
  модулями.
- **TS-клиент**: удалить класс `Analytics` (`src/lib/analytics.ts`) — обёртку
  над Tauri-командами, включая хранилище `analytics.json`, детект устройства и
  дедупликацию ошибок транскрибации.
- **Точки вызова**: убрать импорты и вызовы `Analytics.*` во всех ~25 файлах
  фронтенда (страницы, сайдбар, RecordingControls, DeviceSelection,
  RecordingSettings, LanguageSelection, группы кнопок MeetingDetails,
  RetranscribeDialog, recordingNotification, хуки `useRecordingStop`,
  `useImportAudio`, `useSummaryGeneration`, `useModelConfiguration`,
  `useTemplates`, `ConfigContext`, `SidebarProvider`). В `useRecordingStop`
  убрать в том числе локальный подсчёт встреч и событие `user_activated`
  (они существовали ради аналитики).
- **UI**: удалить `AnalyticsProvider` (и снять обёртку в корневом layout),
  `AnalyticsConsentSwitch`, `AnalyticsDataModal`. Из диалога About и
  PreferenceSettings убрать секцию Usage Analytics вместе с трекингом
  `preferences_viewed` / `notification_settings_changed` /
  `storage_folder_opened`.
- **Документация кода**: убрать аналитические упоминания в комментариях
  (`betaFeatures.ts`, `RecordingPostProcessingProvider.tsx`,
  `language-selection-provider.test.tsx`) и в `LOGGING_OPTIMIZATIONS.md`.
- **Мёртвый код**: `src/lib_old_complex.rs` не был подключён к сборке; файл удалён
  по отдельному запросу пользователя.
- **Локальный файл `analytics.json`**: приложение перестаёт его читать/писать.
  Одноразовая очистка файла у существующих пользователей — опционально,
  в рамках спека не требуется.
- `@tauri-apps/plugin-store` остаётся — используется для `preferences.json`.

## Testing Decisions

Хороший тест здесь проверяет внешнее поведение: приложение компилируется,
существующие тесты компонентов/хуков проходят без моков аналитики, в UI нет
раздела аналитики. Не тестируем «отсутствие кода» юнит-тестами — это проверяется
сборкой, линтом неиспользуемых импортов и ручным прогоном.

- **Seam 1 (высший)**: тесты фронтенда на `bun:test` (`frontend/tests/`). Удалить
  дедикейтед тесты аналитики и моки `src/lib/analytics` из 5 тестовых файлов;
  существующие тесты (recording-controls-stop, device-selection, logo-doodle,
  summary-generation, meeting-details-refresh) должны проходить без
  аналитических моков и ассертов. Prior art: текущие тесты в `frontend/tests/`.
- **Seam 2**: `cargo check` / `cargo test` в `frontend/src-tauri` — компиляция
  после удаления модуля и зависимости; юнит-тесты аналитики удаляются вместе
  с модулем.
- **Seam 3 (ручной)**: `pnpm run tauri:dev` — приложение стартует, в About /
  Preferences нет раздела Usage Analytics, сетевой мониторинг (прокси/файрвол)
  не показывает запросов к posthog.

## Out of Scope

- ~~Удаление мёртвого `src/lib_old_complex.rs`~~ — выполнено по отдельному запросу пользователя.
- Одноразовая миграция, удаляющая `analytics.json` у существующих пользователей.
- Ротация/отзыв PostHog API key — действие в кабинете PostHog, вне репозитория
  (но обязательно после мержа).
- Внутренняя диагностика (audio pipeline stats, notification statistics,
  transcription segments) — не является Usage Analytics и не затрагивается.
- Любые новые механизмы телеметрии/сбора обратной связи.
