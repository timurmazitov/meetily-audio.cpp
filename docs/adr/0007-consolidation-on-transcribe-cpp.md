# 0007. Консолидация транскрибации на transcribe.cpp

> **Статус: принято (2026-11-21).** Supersedes: [ADR 0001](0001-audio-cpp-as-third-engine.md) в части ASR (audio.cpp как движок транскрибации), [ADR 0006](0006-transcribe-cpp-as-fourth-engine.md) в части соседства движков. [ADR 0004](0004-diarization-independent-of-transcription-provider.md) остаётся в силе без изменений.

Локальная транскрибация консолидирована на единственном движке **transcribe.cpp** (провайдер `transcribeCpp`, ADR 0006): движки Whisper (whisper-rs) и Parakeet (ONNX Runtime) удалены полностью, ASR-путь audio.cpp (GigaAM) выведен из транскрибации. Мотивация: четыре движка распознавания в одном приложении — это четыре тяжёлых компилируемых зависимостей (whisper-rs, ONNX Runtime), отдельные компилируемые GPU-сборки (cuda/vulkan/metal/coreml/hipblas/openblas), свои CI-шаги и раздутый UI настроек, при том что transcribe.cpp покрывает нужный набор GGUF-моделей (русские и мультиязычные), активно развивается и не требует компилируемых GPU-фич. ASR audio.cpp дублировал transcribe.cpp, а GigaAM планировался к удалению из каталога audio.cpp.

Что удалено: модули `whisper_engine/` и `parakeet_engine/` со всеми Tauri-командами и событиями, зависимости `whisper-rs` и `ort` из манифеста, компилируемые GPU-фичи Cargo, GPU-скрипты dev/build (`dev-gpu.*`, `build-gpu.*`, `auto-detect-gpu.js`, `tauri-auto.js`), соответствующие CI-шаги (Vulkan SDK ради whisper-rs), UI менеджеров моделей Whisper/Parakeet и ключи i18n. В `audio_cpp_engine/` удалены задача ASR и GigaAM из каталога — модуль содержит только диаризацию Nemotron.

Что сохранено:

- **Диаризация без изменений** (ADR 0004): audio.cpp (модель Nemotron-3 Diarization) выполняет второй этап поверх готового транскрипта, независимо от провайдера транскрибации; секция «Speaker diarization» видна всегда.
- **Runtimовая Vulkan-модель transcribe.cpp** (ADR 0006): prebuilt-рантайм со стейджингом `pnpm run stage:transcribe`, режимы Авто / Vulkan (ГПУ) / CPU, авто-фолбэк на CPU. Компилируемые GPU-сборки приложения при этом отсутствуют: `pnpm run tauri:dev` / `tauri:build` — простые сборки без фич.
- **GGUF-каталог transcribe.cpp с историческими именами** моделей (whisper-large-v3, parakeet-tdt-0.6b-v3, parakeet-ultra, gigaam-v3, qwen3-asr) — это модели transcribe.cpp, а не удалённые движки; имена не меняются.
- **Легаси-колонки БД** `whisperApiKey` и `settings.whisperModel` остаются в схеме (миграции не пишутся); файлы ранее скачанных моделей на диске пользователя не удаляются.
- **Sidecar `llama-helper`** (саммаризация) не затронут, включая его опциональные GPU-фичи и требование libclang для bindgen в `llama-cpp-sys-2`.

Мягкая миграция настроек: значения провайдера из удалённого набора (`localWhisper`, `parakeet`, `audioCpp`) при загрузке конфигурации трактуются как `transcribeCpp` с моделью по умолчанию из каталога (`parakeet-ultra`, Q8_0); API-ключи локальных провайдеров не сохраняются (no-op). Облачные провайдеры транскрибации (Deepgram и др.) остаются schema-live, но UI-dead — их состояние этой задачей не меняется.

Функция авто-перевода удалена целиком: её поддерживал только Whisper; язык транскрипции определяется автоматически.

## Considered Options

- **Оставить Whisper как резервный движок**: отказ отклонён — Whisper тянет whisper-rs с компилируемыми GPU-фичами и отдельными CI-шагами, качеством русской ASR уступает GGUF-моделям каталога (WER fleurs-ru: ~8.4% GigaAM v3, ~5.0% whisper-large-v3 у transcribe.cpp-конвертаций), а поддержкой двух движков никто не пользуется.
- **Сохранить ASR audio.cpp (GigaAM) как лёгкую альтернативу**: отклонено — дублирует transcribe.cpp на тех же GGUF-моделях GigaAM, а upstream планирует убрать GigaAM из каталога audio.cpp; модуль получает одну ответственность (диаризация).
- **Удалить колонки БД и файлы моделей пользователей**: отклонено — миграция схемы рискованнее мягкой миграции значений, а удаление файлов пользователя из-под приложения недопустимо; неиспользуемые колонки безвредны.

## Consequences

- Перечисление движков транскрибации содержит единственный вариант transcribe.cpp; неизвестное значение провайдера при загрузке конфигурации деградирует в `transcribeCpp` с моделью по умолчанию — компилятор и репозиторий настроек гарантируют отсутствие обращений к удалённому.
- Удалённые провайдеры (`localWhisper`, `parakeet`, `audioCpp`) остаются распознанными в мягкой миграции (`REMOVED_TRANSCRIPT_PROVIDERS` в `database/repositories/setting.rs`) и не должны удаляться без новой миграции данных.
- Сборка и CI упрощаются: ни одна сборка приложения не требует CUDA/ROCm/Vulkan SDK; Vulkan SDK в CI остался только там, где он нужен `llama-helper` (Linux-релиз llama-helper с фичей `vulkan`, Windows-devtest).
- Документация и глоссарий описывают единственный движок; ADR 0001/0006 помечены частично устаревшими и сохранены как история.
