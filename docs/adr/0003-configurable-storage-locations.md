# Конфигурируемые пути хранения: папка записей и папка данных приложения

Пользователь может выбирать папки хранения на вкладке General → «Data Storage Locations»: (1) базовую папку записей встреч и (2) корневую папку данных приложения (база SQLite, модели движков, логи, файлы настроек). Ранее всё было привязано к дефолтному app data dir (`%APPDATA%\ai.samobranka.app` на Windows), а сохранённая настройка `save_folder` игнорировалась исполнительным путём.

## Considered Options

- **Перенос данных при смене папки** (копирование БД/моделей с прогрессом, rewrite путей в БД): щадяще для пользователя, но добавляет контур миграции, обработку занятого диска и гонки с живым connection pool. Отклонено — явным решением пользователя: переноса файлов нет ни сейчас, ни потом.
- **Начать с чистого листа при смене папки** (принято): смена папки данных приложения означает пустую базу и повторную загрузку моделей; старое место никогда не удаляется и не модифицируется, возврат указателя на старую папку восстанавливает доступ к данным. Исключение: мелкие JSON-файлы настроек (tauri-plugin-store) копируются, чтобы не терять API-ключи и устройства.
- **Bootstrap-указатель на app data dir**: внутри самой app data dir (chicken-and-egg — при первом запуске на новом месте читать неоткуда). Отклонено.
- **Bootstrap-файл в `config_dir/samobranka/` + env `SAMOBRANKA_DATA_DIR`** (принято, фаза 2): указатель живёт вне данных; env-override — прецедент `SAMOBRANKA_LLAMA_HELPER`.
- **Разделение storage roots (data vs models)** с «оставить модели на месте»: требует переработки `set_models_directory` в четырёх движках. Отклонено.
- **Смена путей на лету без перезапуска**: пути моделей зафиксированы в static-переменных на старте (`lib.rs:659-687`), БД открыта на всю сессию. Отклонено — после смены app data dir приложение перезапускается принудительно.
- **Дублирование настройки папки записей на вкладке Recordings**: два независимых значения уже рассинхронизировались (отображение дефолтного пути вместо фактического). Отклонено — все настройки путей живут только на вкладке General, один источник истины (`RecordingPreferences.save_folder`).

## Consequences

- **Фаза 1 (папка записей)**: сейвер и импорт читают `save_folder` из преференсов (fallback — платформенный дефолт); `select_recording_folder` реализован через `tauri-plugin-dialog`; валидация минимальная — создать при отсутствии, тест записи, предупреждение о свободном месте (< 1 ГБ, не блокер). Настройка применяется к новым записям; существующие записи хранят абсолютные пути (`meetings.folder_path`) и продолжают работать.
- **Фаза 2 (папка данных приложения)**: отдельной фичей — централизованный resolver путей, bootstrap-файл, перезапуск. Сетевые диски для app data запрещены (SQLite WAL по сети — риск коррупции), съёмные — с предупреждением; для папки записей сетевые/съёмные разрешены с предупреждением.
- Показ папки моделей на вкладке General — информационный (путь производен от app data dir), без отдельного выбора.
- Воспроизведение записей идёт через Rust-команды (`read_audio_file`), поэтому scope fs-плагина (`$APPDATA/*`) расширять не нужно.
