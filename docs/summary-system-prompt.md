# Спецификация: настраиваемый системный промпт саммаризации

Статус: решения согласованы (2026-11-17), реализация не начата.
Термины — по `GLOSSARY.md` (базовый системный промпт, системный промпт шаблона, дополнительный контекст саммаризации).

## Контекст

Сегодня системный промпт финального отчёта захардкожен в `build_final_report_system_prompt` (`frontend/src-tauri/src/summary/processor.rs:228-252`); пользователь может влиять на результат только через дополнительный контекст саммаризации (`customPrompt` → `<user_context>` в пользовательском сообщении). Требуется: (1) редактируемый базовый системный промпт в настройках, (2) опциональный системный промпт шаблона, полностью заменяющий базовый.

## Согласованные решения

1. **Базовый системный промпт** — новая настройка на вкладке Summary (`frontend/src/app/settings/page.tsx`, компонент `SummaryModelSettings.tsx`). Хранится в одном месте (таблица `settings` SQLite) и подставляется в момент формирования запроса; редактирование базового промпта сразу действует на все шаблоны без собственного промпта (ничего не «запекается» в шаблоны).
2. **Системный промпт шаблона** — опциональное поле `systemPrompt` в JSON шаблона (кастомные шаблоны в `~/.config/Samobranka/templates/` и bundled-шаблоны в `frontend/src-tauri/templates/`). Задан → полностью заменяет базовый промпт (без конкатенации). Отсутствует или пустое → используется базовый промпт. Редактора шаблонов в UI не строим — указание промпта шаблона = редактирование JSON.
3. **Область действия**: настраиваемый промпт заменяет **только** системный промпт финального отчёта. Внутренние промпты пайплайна (чанк-саммари, комбайн чанков, перевод, нормализация) остаются захардкоженными — они технические; их подмена сломала бы двухпроходную схему (English base → перевод).
4. **Плейсхолдеры**: базовый промпт (и промпт шаблона) хранятся как текст с плейсхолдерами `{section_instructions}` и `{template}`, подставляемыми в момент запроса. Пользователь может переставить или удалить их. В UI под полем — подсказка с доступными плейсхолдерами.
5. **Дефолт**: базовый промпт инициализируется текущим захардкоженным текстом (переносится в константу `DEFAULT_SUMMARY_SYSTEM_PROMPT` с плейсхолдерами); поведение по умолчанию не меняется. В UI — кнопка «Reset to default».
6. **Кэш**: fingerprint `english_cache` (`template_cache_fingerprint`, `summary/service.rs:129-136`) должен учитывать эффективный системный промпт (шаблонный, если задан, иначе базовый) — иначе смена промпта не перегенерирует саммари.
7. **UI поля**: обычное многострочное textarea без валидации содержимого; промпт отправляется модели «как есть». Макросы/переменные сверх плейсхолдеров п. 4 — не делаем.
8. **Дополнительный контекст саммаризации** (`customPrompt` → `<user_context>`) не меняется и работает независимо от обоих системных промптов.

## Замечания к реализации

- `Template` (`summary/templates/types.rs`): добавить `system_prompt: Option<String>` (имя JSON-поля — в согласованном со структурой файлов стиле, см. существующие шаблоны).
- Точка сборки запроса: `processor.rs:490-507` — выбор эффективного промпта: `template.system_prompt` → иначе настройка → иначе дефолт; затем подстановка плейсхолдеров.
- Подмена должна работать для всех провайдеров, включая BuiltInAI (sidecar `llama-helper`): промпт проходит через `format_prompt` (`summary_engine/models.rs:297-315`), изменения в `processor.rs` затронут всех.
- Возврат промпта в UI: если в настройках пусто — отдавать дефолт (seed лениво при первом чтении).
- Тесты: рядом с кодом (Rust `#[cfg(test)]`, фронтенд `bun:test`), покрыть выбор эффективного промпта и подстановку плейсхолдеров.
